# ADR-002: Strict Promote-Only Status Transitions

## Context

The SDD workflow needs one authoritative mechanism for lifecycle changes. If
authoring skills, agents, and humans edit status fields independently, an
artifact can claim approval without passing its prerequisite checks and the
history of the decision becomes unclear.

## Decision

1. Authoring skills create or revise artifacts with `status: draft` only.
2. Every transition, including the first approval, is performed through
   `promote-artifact`.
3. Human confirmation approves the content under review; it does not silently
   change lifecycle status.
4. Gherkin uses the equivalent `# status: ...` comment header.
5. Approved ADRs are immutable. A changed decision requires a successor ADR with
   `supersedes` and a promoted predecessor marked `superseded`.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Let authoring skills approve their own output | Creates two transition authorities and weakens auditability. |
| Allow direct status edits | Bypasses prerequisite validation and makes readiness claims unreliable. |

## Consequences

### Positive

- Lifecycle state has one validation authority.
- Readiness and approval claims are auditable.
- Agents cannot accidentally skip semantic review.

### Negative Or Tradeoffs

- Each artifact requires an explicit promotion step.
- Simple one-pass authoring is intentionally not treated as approval.

## Follow-Up Actions

- Keep authoring skills draft-only.
- Keep `promote-artifact` checklists aligned with `SDD_WORKFLOW.md`.
