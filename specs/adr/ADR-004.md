# ADR-004: Feature Packets Stay Flat

## Context

Feature packets need stable paths for agents, exports, archives, and history.
Physical nesting under an epic duplicates ownership already represented by
artifact relationships.

## Decision

Feature packets remain flat at:

```text
specs/NNN-feature-slug/
```

Epic ownership is recorded in frontmatter using `parent: PRD-NNN` and
`epic: EPIC-NNN`. `promote-artifact` validates that the referenced epic brief
exists and is approved.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Nest packets under epic directories | Duplicates ownership, deepens paths, and makes re-parenting and archiving noisy. |
| Encode the epic in the packet slug | Couples a human-facing slug to hierarchy and still duplicates metadata. |

## Consequences

### Positive

- Packet paths remain stable when ownership changes.
- Agents and CI can use simple packet globs.
- Archive paths preserve the same packet identity.

### Negative Or Tradeoffs

- Finding all slices of an epic requires frontmatter filtering.
- The specs root contains one directory per feature slice.

## Follow-Up Actions

- Keep packet ownership in frontmatter.
- Validate epic linkage during story and packet promotion.
